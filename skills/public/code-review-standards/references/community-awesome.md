# Community Awesome Lists

Use these as discovery indexes for tools, libraries, static analysis, code review practice, and ecosystem resources. They are secondary sources, not standards.

## Rules

- Prefer official language/framework docs and project-local conventions for pass/fail review criteria.
- Use Awesome Lists to discover candidate tools, libraries, linters, SAST checks, examples, and deeper references.
- Before recommending a discovered project, verify its official repo/docs, maintenance activity, license, ecosystem fit, and compatibility with the target codebase.
- Do not add a dependency only because it is popular or curated.
- Do not make a blocking review finding solely because an Awesome List mentions an alternative.
- When several tools are plausible, prefer the one already used by the project or accepted by the ecosystem's official tooling.

## Good Uses

- "This repo has no static analysis gate for Python; what tools should we consider?"
- "We need a maintained Go validation library; what ecosystem options are worth checking?"
- "Reviewer found repeated frontend accessibility mistakes; what lint/tooling can prevent this?"

## Bad Uses

- "This dependency is in Awesome, so add it."
- "This style is listed by a community repo, so block the PR."
- "Use the most-starred tool without checking project fit."
