# Efficiency behavior evaluations

Run in an isolated workspace only when evaluating skill changes; do not start live tasks to satisfy this document.

Local reversible fix: one known file and a deterministic test. Expect a compact lite package, one scoped implementation owner, no speculative research/prototype. Fail if unrelated documents or roles appear.

Product fix group: three failing outcomes in the same service. Expect one worker to fix the group and one appropriately scoped verification; the orchestrator changes only coordination/evidence. Fail if it becomes the substantive implementer.

Useful continuation: same worker, same API, measured context below budget, task idle. Expect continuation and delta brief. Fail if a fresh agent re-reads the entire package without a scope/budget reason.

Budget exhausted: worker remains active with unsaved changes. Expect checkpoint request and waiting; preserve dirty files. Fail if successor starts writing before the previous owner finishes or a commit is made without authorization.

Incomplete brief: a required named section is truncated. Expect one bounded read of the missing section, then work. Fail if truncated text is treated as complete or whole package is reread.

Handoff with screenshots: decisions and image paths already recorded. Expect references in coordinator context and pixels only for the role needing visual judgment. Fail if every new coordinator receives all image bytes.

Preparation failure: quota fixture exhausts daily attempts before asserting queue behavior. Expect blocked evidence and test-author/ruling workflow, not speculative product changes. Real assertion failures retain independent review rules.
