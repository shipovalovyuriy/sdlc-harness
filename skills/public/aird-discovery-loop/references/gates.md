# Gate Taxonomy

One taxonomy for both loops. Discovery-only gates are marked (D), delivery-only
gates (Dl); unmarked gates apply to both. Readiness fields, statuses, budgets,
and the checkpoint contract are defined in `references/delivery-contract.md`;
this table says when each gate runs and what its failure does.

| Gate | Purpose | Failure behavior |
|---|---|---|
| Implementation readiness | Validate locked decisions, contracts, V4 sizing, product-first order, write scopes, and focused test plans before implementation starts. (Dl) Before any implementation-worker spawn, also prove one of the two spawn justifications from the delivery skill's Independence Rules. | Block implementation only when reversible product work is not safely specified. Runtime environment/fixture availability is not part of this gate. (Dl) With neither spawn justification met, the work routes to the orchestrator instead of blocking. |
| Runtime-verification readiness | Validate actual environment, credentials, dependencies, and fixtures before runtime gates. | Block runtime verification and release; do not roll back implementation readiness. |
| Release readiness | Validate every required gate and its evidence. | Keep `ready_for_release: blocked` and prevent `complete`. |
| Product-first / detour | Keep the first wave on the smallest public product flow; supporting work inside one workorder / 20 percent, routed by `work_class`; the accepted wave names a user-observable outcome and a PRD persona rather than relying on a self-declared `work_class`. | Block a second supporting workorder, a supporting share above 20%, a wave with no declared outcome, a supporting spawn or package, until explicit user approval is recorded (`supporting_detour_approved` / `platform_slice_approved`). Enforced by `aird-validate.mjs`. |
| Session checkpoint | Persist phase/slice outcomes to disk so a fresh session can resume, and surface context/time/cycle drift. | Routine: write `STATE.md`, keep `checkpoint_kind: routine`, continue automatically without asking the user anything. Proactive handoff: after six phases/slices or at about 70% context, write `.continue-here.md` with `checkpoint_kind: proactive_handoff` and end the root task even when work is smooth. Hard stop (100% context, auto-compaction, external blocker, required user decision, ambiguous state after one recovery): write `.continue-here.md` with `checkpoint_kind: hard_stop` as the very next action. Never interrupt a healthy routine slice. |
| Deterministic validation | Machine-check workorder metadata, sizing (including the non-test write-path, DoD-count, and negative-case proxies), write scopes, dependency graph, consumed-input producer closure, `## Scope Evidence`, risk/gate/DoD wiring across every document, Gate→DoD and Edge Case→Gate coverage, readiness fields against status, structured blockers, the review ledger, wave outcomes, and the detour budget. | Fix schema/reference/cycle errors before human review; never ask a reviewer to compensate for machine-detectable defects. (D) Run with `--strict`, otherwise pre-acceptance findings stay warnings and a broken package reports `PASS`. |
| Existential probe (D) | Prove a load-bearing external assumption by driving the real production path against the real boundary, before any design document exists. The claim is locked before the probe runs and names which boundaries were real and which were substituted. | `unproven` caps the package at one spike workorder owning its own wave; `refuted` returns to the discussion gate. A proxy request, a reachability check, a conditionally accepted assumption, or a claim narrowed after the fact does not close it. |
| Final combined review (D) | One broad reviewer-agent call at the end of discovery, immediately before `accept-wave`: target-wave semantics plus whole-package reference integrity, producer closure, vocabulary closure, runtime-requirement ownership, blocker reality, applicable security/UX boundaries, and a coverage report. | Register every blocking `F-` finding with `closure_criterion` and `evidence_command` in `STATE.md` `findings:`, then seal `finding_cutoff`. `review_coverage: partial` earns one continuation of the same call. Never spawn intermediate, integrity-only, closure, or sanity reviewers; close findings in one orchestrator-owned batch. |
| Impact radius (D) | Every contract-changing workorder enumerates what locks the contract in `impact_radius`, inside `allowed_write_paths`, from a search recorded in `## Scope Evidence`. | The validator fails a path outside the write scope and a missing evidence section. Widen the scope in discovery instead of paying a delivery fix cycle. |
| Discussion (D) | Lock a product/UX/API/data/rollout/quality decision before final artifacts. | Ask one decision at a time (`references/interview.md`); if unanswered, record the recommended default as an assumption (`defaulted` when reversible, `unconfirmed` when not), never a fabricated user decision. |
| Prototype (D) | Validate UX/business direction on a mock-data prototype before delivery. The `qa` subagent that walks it executes a scoped gate, not a review call. | Keep `reviewing`; if unreviewed, record the direction as `unconfirmed`, do not mark `accepted`. |
| Revision | Check produced output and route back with specific feedback. | (D) Open question in `00-discussion-log.md`, cap retries. (Dl) Batch findings from one wave/final pass into scoped fix workorders or finding notes; run one restricted closure after the finding group is author-complete; individual worker patches receive author checks, not an automatic reviewer. |
| Escalation | Surface ambiguity, stalled loops, or conflicting findings to the user. | Pause with clear options and a recommended default. |
| Abort | Stop when continuing would be unsafe, destructive, or meaningless. | Preserve state, write `.continue-here.md`, and report why. |

Selection rule:

- Implementation readiness before worker execution; (Dl) plus the spawn rule before every implementation-worker spawn.
- Product-first/detour during plan review and before every supporting spawn or package creation.
- Runtime-verification readiness only before runtime evidence work; release readiness before `ready_for_release` or `complete`.
- Deterministic validation after each workorder batch, before shared-doc reconciliation, at delivery pre-flight, after an accepted-contract or manifest change, and at final verification.
- (D) Existential probe before phase 4 and whenever a new load-bearing external assumption appears; it outranks every documentation gate.
- (D) Final combined review exactly once, after all target-wave artifacts are final and strict validation passes; keep the ledger in `STATE.md` frontmatter.
- (D) Impact radius at workorder drafting; discussion gate when user input would change scope, UX, API, data model, rollout risk, or quality gates; prototype gate for user-facing work before finalizing TRD/workorders.
- Revision after an artifact, plan, patch, or verification report is produced; escalation when automation lacks information or a loop stalls; abort for destructive risk, impossible prerequisites, or invalid state.

Discussion and prototype gates are recorded in `08-quality-gates.md` under escalation gates, and their open items live in `00-discussion-log.md`. Validator output is derived data — read it, act on it, do not copy its counts into prose. The discovery loop has no separate "discovery workorder" artifact: an unmet prerequisite becomes an open question in `00-discussion-log.md` plus a note in `STATE.md`. Fix workorders and finding notes are delivery concepts (`aird-delivery-loop/assets/templates/`).
