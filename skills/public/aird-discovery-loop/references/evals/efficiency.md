# Profile behavior evaluations

A typo in a known existing screen: lite, one scoped task, existing UI reference, affected-state verification; no research, architect or prototype without an unresolved question.

One-service feature with a known public contract: standard; document the actual boundary and required runtime tests, not unrelated system design.

One-line authorization change or migration: deep despite the small diff; required security/upgrade evidence remains required.

An external API assumption becomes uncertain: raise profile, record why, preserve accepted work and investigate the specific assumption before dependent implementation.

An old accepted package has no efficiency_policy: retain its rules and hashes; do not silently reclassify it.
