# E-0028 — API библиотеки доказывается по установленной версии, а не по документации

- Источник: улучшения AIRD от 03.11.2026; воспроизводимые условия приведены ниже.
- Класс: scope
- Сценарий: задание опирается на опцию, функцию или флаг сторонней библиотеки, а Scope Evidence построено по документации или памяти, без проверки установленной версии.
- Ожидаемое поведение лупа: discovery до приёмки волны показывает в Scope Evidence установленную версию (`npm ls <pkg>` / `go list -m <module>`) и `grep` по исходникам пакета; если API нет, задание само называет замену или обновление как записанное решение, и исполнитель его не «открывает».
- Какое правило это гарантирует: `aird-discovery-loop/SKILL.md` § Consumes (абзац «A library API is `exists-in-repo` only in the installed version») и `references/delivery-contract.md` § Consumes. Обе копии: Claude и Codex.
- Проверка: сверка контракта discovery; отдельный запуск модели для поведенческой оценки в рамках публикации не выполнялся.
