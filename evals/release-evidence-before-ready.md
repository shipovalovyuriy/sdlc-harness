# E-0032 — Сводный PASS не скрывает невыполненную обязательную проверку

- Источник: аудит и исправление AIRD, 13.11.2026; воспроизводимые условия приведены ниже.
- Класс: evidence
- Сценарий: статус `ready_for_release` или `complete` заявлен без runtime/UI-доказательств; либо сводные счётчики показывают успех, а текущая обязательная строка имеет fail/blocked-no-evidence/waived/skipped/pending, пустой результат, нулевое выполнение или ненулевые падения/пропуски. Ещё один обход — принять волну, оставить её задание незавершённым и заявить готовность.
- Ожидаемое поведение лупа: CLI возвращает exit 1 и `ok: false` для таких состояний. Все задания принятых волн должны быть done; непринятый черновой бэклог не блокирует. Корректные доказательства проходят. Описание прошлой исправленной ошибки, в том числе отдельная историческая таблица, не считается текущим провалом. Явно необязательная диагностика не превращается в обязательную проверку.
- Какое правило это гарантирует: `aird-delivery-loop/assets/scripts/aird-validate.mjs` §§ inspectVerificationRows и releaseReady; `assets/templates/backend-verification.md` § Required Check Accounting; обе копии, Codex и Claude.
- Проверка: настоящие CLI-прогоны в `aird-validate.test.mjs`, блок Release readiness; проверяются код завершения, JSON и причина отказа. Для обеих копий — 163 сценария, 0 падений и пропусков.
