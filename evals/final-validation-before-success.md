# E-0033 — Ошибка финального валидатора запрещает сообщение об успехе

- Источник: аудит и исправление AIRD, 13.11.2026; воспроизводимые условия приведены ниже.
- Класс: evidence
- Сценарий: после последних правок статуса и доказательств валидатор выдаёт ненулевой код или `ok: false`; либо проверка относится к прежней версии файлов.
- Ожидаемое поведение лупа: сохранить JSON в `evidence/final-validation.json`; успех разрешён только при exit 0, `ok: true` и JSON `status`, совпадающем с объявляемым `ready_for_release` либо `complete`; PASS для discovery/verifying/paused не доказывает готовность к выпуску. При ошибке сохранить исходный отчёт, поставить paused / ready_for_release: blocked и сообщить конкретные ошибки. Новая правка требует нового прогона. Согласование исключения не увеличивает число успешных проверок.
- Какое правило это гарантирует: `aird-delivery-loop/SKILL.md` § Completion Criteria, протокол последней проверки; обе копии, с путями команд своего рантайма.
- Проверка: сверка текста обеих копий; интеграционные тесты валидатора проверяют его реальные результаты. Способность текста заставить модель соблюдать протокол отдельно не измерялась.
