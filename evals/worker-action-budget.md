# E-0037 — Воркер реализации получает свои разделы в брифе, читает кусками и не растягивается на сотни шагов

- Источник: улучшения AIRD от 17.11.2026. В deep-delivery шесть воркеров на Sonnet с effort `xhigh` потратили 166 млн токенов за 2 ч 47 мин, и сработал 5-часовой лимит подписки. 98 % — повторное чтение контекста. Самый длинный воркер сделал 158 действий: контекст дорос до 536 тыс., итог 58 млн. Короткий: 56 действий, 230 тыс., 10 млн. До первой правки самый длинный воркер прочитал 149 тыс. символов документов пакета целиком, все 7 справочников стандартов и 178 тыс. символов кода вокруг. Пункты `docs_to_read` с двоеточием в заголовке Software Factory теряла при разборе. Слепой автор приёмки ушёл в обход Factory как встроенный субагент на Opus: Factory не поддерживала приёмку для нескольких репозиториев.
- Класс: cost
- Ожидаемое поведение лупа:
  1. Воркер delivery получает в брифе разделы `docs_to_read` своего воркордера, вырезанные по заголовкам, и не открывает документы пакета целиком.
  2. Бриф каждого агента требует читать кусками (`rg -n`, затем `sed -n` окном до 80 строк), открывать справочники скилла по одному и писать длинный вывод в файл.
  3. Для нового воркера Factory предупреждает при первом из порогов: 60 действий, 120 тыс. токенов контекста или 40% окна. При 80 действиях, 160 тыс. или 50% окна воркер сохраняет `evidence/<WO>-progress.md` и возвращает «частично». Преемник получает записку после остановки прежнего исполнителя. Коммит делается при наличии разрешения.
  4. Субагенты запускаются только через `sf_spawn_agent`. Слепая приёмка работает и для нескольких репозиториев: отдельный репозиторий набора, база — коммит каждого репозитория, проверка на базе — на копии пространства.
  5. Factory показывает токены каждого агента, сумму по провайдерам и последнее сообщение провайдера о лимите подписки.
- Какое правило это гарантирует: `aird-delivery-loop/SKILL.md` (стоимость воркера, `test-author` только через Factory), плагин Software Factory (`src/sections.ts`, `agentPrompt`, `checkWorkerBudgets`, приёмка для нескольких репозиториев), тесты `tests/usage.test.ts` и `tests/workspace-acceptance.test.ts`.
- Проверка: тесты плагина (45) проходят. Отдельный запуск модели для поведенческой оценки не выполнялся.
